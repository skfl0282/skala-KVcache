## SUMMARY

본 보고서는 데이터센터·클라우드 서빙 환경에서 LLM 추론의 핵심 병목인 KV 캐시 및 모델 가중치의 메모리 문제를 대상으로, 소프트웨어 기술인 **DeepSeek-V2의 Multi-head Latent Attention(MLA)**와 하드웨어·시스템 기술인 **ITME(Inference Tiered Memory Expansion)**를 평가하였다.

MLA는 어텐션의 Key-Value 표현을 저랭크 latent vector로 공동 압축하여 KV 캐시 자체의 크기를 줄이는 모델 내부 최적화 기술이다. DeepSeek-V2 및 SGLang 구현 자료에서는 KV 캐시 감소와 처리량 개선 가능성이 제시되어 있으며, 오픈소스 모델 및 추론 프레임워크와 연결된 개발자 실험 생태계가 확인된다. 다만 일반적인 추론 시스템에서 동일 성능을 재현하려면 전용 커널과 런타임 최적화가 필요하며, 상용 서비스 기반의 장기 운영 성과는 추가 검증이 필요하다.

ITME는 CXL 하이브리드 메모리, DRAM 캐시, SSD 및 RDMA를 결합하여 GPU 외부에 대규모 계층형 메모리를 구성하는 인프라 기술이다. 대형 모델 가중치와 장기 세션 KV 캐시를 GPU HBM 밖에 유지하는 데 적합할 가능성이 있으나, 현재 제공 근거는 FPGA 프로토타입과 제한된 워크로드 평가 중심이다. 실제 클라우드 멀티테넌트 환경에서의 P99 지연시간, I/O 경합, 장애 복구, 보안 및 운영비 검증은 부족하다.

두 기술은 대체 관계보다 보완 관계로 해석하는 것이 타당하다. MLA가 저장해야 할 KV 캐시의 기본 크기를 줄이고, ITME가 장기 세션 상태와 대규모 가중치를 외부 계층에 수용하는 결합 구조가 가능하다. 다만 실제 도입 판단을 위해서는 동일 워크로드 조건에서 tokens/s/GPU, 최대 동시성, P95/P99 지연시간, 캐시 적중률, 전력, 운영비 및 장애 복구 성능을 함께 검증해야 한다.

## 1. 분석 배경

LLM의 자동회귀 생성 과정에서는 이전 토큰의 어텐션 계산 결과인 Key와 Value를 이후 토큰 생성에 재사용하기 위해 KV 캐시를 유지한다. KV 캐시는 동일 컨텍스트를 반복 계산하지 않도록 하여 생성 속도를 높이는 데 필요하지만, 입력 길이·출력 길이·동시 요청 수·대화 턴 수가 증가할수록 지속적으로 누적된다.

특히 데이터센터·클라우드 환경에서는 다음과 같은 워크로드에서 KV 캐시가 주요 병목이 될 수 있다.

- 128K급 장문 컨텍스트 처리
- 멀티턴 대화 및 에이전트형 AI
- 다수 사용자의 동시 추론 요청
- 프리픽스 캐시 및 세션 상태 재사용
- 대형 모델 가중치와 KV 캐시의 동시 수용

GPU HBM은 높은 대역폭을 제공하지만 용량이 제한되어 있으며, KV 캐시와 모델 가중치가 HBM을 동시에 점유할 경우 동시성 저하, 캐시 축출, CPU·스토리지 오프로딩 증가 또는 추가 GPU 투입으로 이어질 수 있다. 이에 따라 본 평가는 다음의 두 접근을 비교·분석하였다.

- **MLA:** 필요한 KV 캐시의 크기 자체를 줄이는 모델·소프트웨어 계층 접근
- **ITME:** GPU 외부의 계층형 메모리를 활용하여 저장 가능한 상태 용량을 확장하는 하드웨어·시스템 계층 접근

## 2. 기술 선정

### 2.1 선정 기술

| 구분 | 선정 기술 | 기술 계층 | 핵심 목적 |
|---|---|---|---|
| SW | DeepSeek-V2의 Multi-head Latent Attention(MLA) | 모델·추론 런타임 | KV 캐시 표현 압축 및 추론 메모리 효율화 |
| HW | ITME(Inference Tiered Memory Expansion) | 메모리·서버 인프라 | CXL·DRAM·SSD·RDMA 기반 계층형 메모리 확장 |

### 2.2 선정 이유

두 기술은 모두 LLM 추론에서 발생하는 메모리 병목을 대상으로 하지만, 해결 방식과 적용 계층이 상이하다.

DeepSeek-V2의 MLA는 Key-Value를 저랭크 latent 표현으로 공동 압축하여 KV 캐시 저장량을 줄인다. 장문 컨텍스트 및 높은 동시성 상황에서 GPU HBM 내 KV 캐시 점유율을 낮추는 데 적합한 접근이다.

ITME는 CXL 하이브리드 메모리와 SSD 기반 저장공간을 원격 메모리 계층으로 활용하여, GPU HBM 및 호스트 메모리만으로는 수용하기 어려운 대형 모델 가중치와 장기 세션 상태를 유지하려는 접근이다.

따라서 두 기술은 동일한 메모리 병목을 서로 다른 계층에서 다루며, 데이터센터·클라우드 서빙 환경에서의 결합 가능성을 평가하기에 적합하다.

## 3. 기술 개요

### 3.1 SW 기술: DeepSeek-V2의 Multi-head Latent Attention(MLA)

MLA는 기존 Multi-Head Attention의 Key-Value 표현을 저랭크 방식으로 공동 압축하고, 이를 latent vector 형태로 저장하는 어텐션 구조다. 생성 과정에서 누적되는 KV 캐시의 메모리 요구량을 줄이는 것이 핵심 목적이다.

DeepSeek-V2 관련 자료에서는 MLA를 통해 KV 캐시를 약 93.3% 줄이고 최대 생성 처리량을 5.76배 높였다고 제시한다. 다만 처리량 수치는 특정 모델, 하드웨어, 배치 크기 및 평가 조건에 의존할 수 있으므로 데이터센터 일반 환경의 성능으로 확대 해석하기는 어렵다.

SGLang v0.3에서는 MLA 최적화를 위해 weight absorption, grouped decoding kernel, FP8 batched MatMul, FP8 KV-cache quantization 등이 구현되었으며, H100 기반 벤치마크에서 기준 시스템 대비 3~7배 높은 처리량이 보고되었다. 이 역시 특정 최적화 구성과 벤치마크 환경에 기반한 결과로 해석할 필요가 있다.

#### 적용 가능 영역
- 장문 컨텍스트 기반 LLM 서빙
- 대규모 동시 요청 처리
- 멀티턴 대화 및 에이전트형 AI
- MoE 기반 대형 언어 모델의 추론
- GPU HBM 내 KV 캐시 점유율 완화가 필요한 환경

#### 한계 및 리스크
- MLA는 기존 MHA와 다른 연산 구조를 가지므로 전용 커널 및 런타임 최적화가 필요하다.
- 일반적인 추론 시스템에서는 MLA의 잠재적 효율을 충분히 얻기 어려울 수 있다.
- 대형 MoE 모델의 전체 가중치 용량, 전문가 라우팅 통신, 멀티 GPU·멀티노드 네트워크 병목은 별도 과제로 남는다.
- KV 캐시 압축에 따른 정확도 변화, 학습 비용 증가 및 범용 시스템에서의 재현성에 대한 정량 근거는 제공 자료에서 제한적이다.
- 상용 서비스 장기 운영 사례와 TCO 절감 효과는 추가 검증이 필요하다.

### 3.2 HW 기술: ITME(Inference Tiered Memory Expansion)

ITME는 CXL 하이브리드 메모리와 SSD 기반 저장공간을 결합하여, GPU 서버가 대규모 모델 가중치와 KV 캐시를 원격 메모리 계층에서 접근하도록 하는 계층형 메모리 확장 아키텍처다.

ITME는 내부 DRAM 캐시, 하드웨어 프리페처 및 DMA 기반 다중 계층 프리페칭을 사용한다. 모델 가중치가 레이어 순서에 따라 소비되고 장문 프리픽스 KV 캐시가 순차적 복원 패턴을 가질 수 있다는 점을 활용해, 데이터 이동과 GPU 연산을 중첩하는 구조를 지향한다.

제공 자료에서는 128개 동시 대화와 최대 5턴의 ShareGPT 워크로드에서, 확장된 턴 구간 기준 CPU 오프로딩 대비 최대 35.7% 처리량 향상이 제시되었다. 다만 이는 특정 프로토타입 및 워크로드 조건에서 측정된 결과로, 일반적인 클라우드 서빙 환경의 성능으로 일반화하기는 어렵다.

#### 적용 가능 영역
- 장문 컨텍스트와 멀티턴 대화 기반 LLM 추론
- 에이전트형 AI의 장기 세션 상태 저장 및 재사용
- GPU HBM에 수용하기 어려운 대형 모델 가중치 관리
- 대규모 프리픽스 캐시 및 KV 캐시 보존
- GPU·호스트 메모리 용량 한계를 보완해야 하는 서버 환경

#### 한계 및 리스크
- 원격 메모리 성능은 RDMA 네트워크, CXL 연결, SSD 대역폭, DRAM 캐시 적중률 및 I/O 경합에 영향을 받는다.
- 프리페치 예측이 실패하거나 불규칙한 접근 패턴이 발생하면 GPU 스톨과 tail latency 증가 가능성이 있다.
- CXL, RDMA, RNIC, SSD, DRAM 캐시, QoS, 장애 복구를 함께 운영해야 하므로 시스템 복잡성이 증가한다.
- 세션 격리, 멀티테넌트 보안, SSD 쓰기 내구성, 데이터 일관성 및 장애 복구 정책은 추가 설계가 필요하다.
- FPGA 프로토타입 중심의 실증이므로, 상용 클라우드 환경에서의 장기 안정성 및 운영비는 추가 검증 필요하다.

## 4. 관점별 평가

### 4.1 기술 성숙도 관점

| 구분 | DeepSeek-V2 MLA | ITME |
|---|---|---|
| 추정 TRL | TRL 6 | TRL 5 |
| 실증 근거 | 공개 모델 구조, SGLang 구현, H100 기반 벤치마크 | FPGA 프로토타입, LLM 추론 워크로드 평가 |
| 성숙도 해석 | 관련 환경에서 구현·실증 단계까지 진전 | 기능 검증 및 프로토타입 실증 단계 |
| 주요 검증 과제 | 범용 런타임 재현성, 정확도·학습비용, 상용 운영 안정성 | 상용 서버 확장성, 네트워크 경합, 장애 복구, 멀티테넌시 |

MLA는 공개 모델 구조와 오픈소스 구현, H100 기반 성능 평가가 제시되어 있어 관련 환경에서의 프로토타입 실증 단계로 판단할 수 있다. 그러나 실제 상용 서비스 적용이나 장기 운영 사례는 제공 자료에서 확인되지 않으므로 TRL 7 이상으로 판단할 근거는 부족하다.

ITME는 FPGA 프로토타입과 LLM 워크로드 기반 실측 결과가 제시되었으나, 상용 서버 환경 및 실제 클라우드 운영 환경에서의 장기 검증은 부족하다. 따라서 현 단계에서는 계층형 메모리 확장 가능성을 검증한 연구·프로토타입 단계로 해석하는 것이 타당하다.

### 4.2 시장성 관점

MLA는 LLM 추론 효율화, GPU 메모리 절감 및 긴 컨텍스트 지원 수요와 연결된다. DeepSeek-V2 모델 공개, Hugging Face Transformers 지원, vLLM 및 SGLang 관련 구현 흐름 등으로 인해 개발자·연구자 접근성이 존재한다.

다만 MLA 자체의 시장 규모, 매출, 시장점유율, CAGR, 실제 도입 기업 수 및 고객 사례에 대한 정량 자료는 확인되지 않았다. 따라서 MLA의 시장성은 독립 시장 지표가 아니라 오픈소스 생태계 접근성 및 LLM 추론 최적화 수요를 중심으로 정성적으로 평가해야 한다.

ITME는 CXL, 메모리 풀링, 계층형 스토리지, AI 인프라 확장 수요와 연계될 가능성이 있다. 그러나 제품화, 상용 라이선스, 고객 도입, 서버 제조사 채택, 표준화 컨소시엄 지원 및 시장 규모에 대한 근거는 부족하다.

| 평가 항목 | DeepSeek-V2 MLA | ITME |
|---|---|---|
| 시장 규모·CAGR | 근거 부족 | 근거 부족 |
| 상용 도입 기업 수 | 확인되지 않음 | 확인되지 않음 |
| 개발자 접근성 | 공개 모델·도구 기반의 접근성 확인 | 인프라 통합 필요로 도입 장벽 존재 |
| 생태계 신호 | 오픈소스·개발자 커뮤니티 중심 신호 존재 | 연구 논문 및 프로토타입 중심 |
| 상용화 근거 | 추가 검증 필요 | 추가 검증 필요 |

### 4.3 이해관계자 관점

MLA는 개발자 커뮤니티, 기술 블로그, 모델 리뷰 및 TransMLA와 같은 변환 기술을 통해 연구·실험 차원의 관심이 확인된다. TransMLA는 기존 MHA/GQA 모델을 MLA 방식으로 전환하여 DeepSeek 코드베이스와 vLLM 최적화를 활용하는 접근으로 소개되며, MLA가 특정 모델에 한정되지 않고 확장 가능한 최적화 계층으로 검토되고 있음을 보여준다.

그러나 주요 경쟁사의 공식 대응, 대형 클라우드 사업자의 실제 도입, 기업별 서비스 운영 사례, 투자기관의 정량 평가 등은 제공 자료에서 충분히 확인되지 않는다.

ITME는 연구 논문에서 CPU 오프로딩, NVMe-oF, JBOF, 원격 스토리지 및 재계산 기반 접근과 비교되는 기술적 포지셔닝이 제시된다. 다만 외부 기업 도입, 상용 제품 발표, 경쟁사 공식 반응, 투자기관 평가 및 업계 매체 보도는 확인하기 어렵다.

따라서 이해관계자 관점에서 MLA는 개발자 수용 및 실험 가능성 신호가 확인되는 단계이며, ITME는 연구 중심의 기술 검증 단계로 해석할 수 있다. 두 기술 모두 실제 사업화 신호와 기술적 관심을 구분하여 평가할 필요가 있다.

### 4.4 데이터센터·클라우드 서빙 관점

#### DeepSeek-V2 MLA

MLA는 KV 캐시의 저장량을 줄여 GPU HBM 내에서 더 긴 컨텍스트 또는 더 많은 동시 세션을 수용할 가능성을 제공한다. 특히 긴 컨텍스트, 높은 동시성, 장문 질의 및 에이전트형 워크로드에서 메모리 병목을 낮추는 데 적합하다.

다만 DeepSeek-V2는 전체 가중치 규모가 크므로, 토큰당 활성 파라미터가 제한된 MoE 구조라고 하더라도 단일 GPU 서버에서 쉽게 운영된다고 단정하기 어렵다. 모델 병렬화, 양자화, 다중 GPU 구성 또는 외부 메모리 계층이 필요할 수 있다.

#### ITME

ITME는 GPU HBM에 모두 수용하기 어려운 대형 모델 가중치, 장기 KV 캐시 및 멀티턴 세션 상태를 외부 계층에 유지하는 데 적합할 가능성이 있다. 장기 세션 재사용률이 높고, 가중치 접근 및 KV 복원 패턴이 비교적 예측 가능한 워크로드에서 효과가 기대된다.

반면, 불규칙한 멀티테넌트 요청, 낮은 캐시 적중률, 네트워크 I/O 경합 및 프리페치 실패 상황에서는 성능이 저하될 수 있다. 특히 P95/P99 지연시간과 장애 상황에서의 서비스 수준은 추가 검증이 필요하다.

#### 결합 적용 가능성

두 기술은 상호 보완적으로 구성될 수 있다.

1. **GPU HBM:** 현재 디코딩에 필요한 활성 가중치와 활성 KV 캐시  
2. **호스트/CXL DRAM:** 자주 재사용되는 프리픽스 캐시 및 다음 레이어 데이터  
3. **ITME 기반 SSD 계층:** 대규모 모델 가중치와 장기 세션 상태  
4. **원격 공유 스토리지:** 저빈도 세션 및 백업 아카이브  

MLA가 KV 캐시의 기본 크기를 낮추고, ITME가 장기 보존이 필요한 상태와 대규모 가중치를 계층형 메모리에 수용하는 구조는 데이터센터 서빙 환경에서 검토할 수 있다. 다만 해당 결합 구성의 실제 효율은 워크로드 특성, 캐시 적중률, RDMA·CXL·SSD 대역폭, GPU 구성 및 운영 정책에 따라 달라질 수 있다.

## 5. 시사점

### 5.1 KV 캐시 병목은 단일 기술로 해결하기 어렵다

LLM 서빙의 메모리 병목은 KV 캐시 크기, 모델 가중치, GPU HBM 용량, 네트워크 전송, 스토리지 대역폭 및 동시성 정책이 함께 작용하는 문제다. 따라서 모델 수준의 압축 기술과 인프라 수준의 메모리 확장 기술을 분리해 검토할 필요가 있다.

### 5.2 MLA는 메모리 요구량 축소에 적합하다

MLA는 저장해야 할 KV 캐시 자체를 줄이는 접근이다. 짧은 요청과 높은 처리량이 중요하거나, GPU HBM 내 KV 캐시 점유율이 병목인 환경에서는 우선 검토 가치가 있다. 다만 전용 커널과 추론 런타임 지원 여부가 실제 성능을 좌우한다.

### 5.3 ITME는 장기 상태 보존과 대용량 확장에 적합하다

ITME는 장문 컨텍스트, 멀티턴 에이전트, 대규모 프리픽스 캐시, 대형 가중치 관리처럼 GPU HBM을 넘어서는 상태 유지가 필요한 환경에서 의미가 있다. 그러나 시스템 복잡성 및 원격 계층 지연 문제를 고려해야 하며, 단순한 메모리 증설 방식으로 이해해서는 안 된다.

### 5.4 워크로드별 적용 전략이 필요하다

- **짧은 요청·높은 단일 노드 처리량 중심:** MLA 우선 검토
- **장문 컨텍스트·높은 동시성 중심:** MLA와 캐시 관리 최적화 병행
- **멀티턴 에이전트·세션 재사용 중심:** MLA와 계층형 메모리 구조 병행 검토
- **대형 모델 가중치·장기 상태 수용 필요:** ITME와 같은 외부 메모리 계층 검토

### 5.5 실도입 전 공통 검증 항목

실제 도입 의사결정 전에는 다음 항목을 동일 워크로드에서 측정해야 한다.

- tokens/s/GPU
- 최대 동시 요청 수
- P95/P99 지연시간
- 프리필 및 디코딩 구간별 성능
- KV 캐시 적중률 및 축출 빈도
- GPU·네트워크·스토리지 사용률
- 전력 사용량
- 달러/백만 토큰
- 장애 복구 시간 및 서비스 영향 범위
- 멀티테넌트 보안·QoS 정책

## 6. 한계점

본 보고서는 제공된 공개 자료와 Agent 평가 결과에 기반한 정성적 분석이다. 따라서 실제 서비스 운영 환경의 성능, 비용 및 안정성을 직접 보장하지 않는다.

첫째, MLA와 ITME 모두 실제 대규모 상용 서비스의 장기 운영 사례가 충분히 확인되지 않았다. 특히 대규모 멀티테넌트 환경에서의 P99 지연시간, 장애 복구, 보안, 운영 인력 부담, 장기 SSD 내구성 및 TCO 관련 자료는 부족하다.

둘째, MLA의 KV 캐시 감소 및 처리량 개선 수치, ITME의 CPU 오프로딩 대비 처리량 개선 수치는 특정 모델·하드웨어·배치·워크로드·프로토타입 조건에 기반한다. 이를 일반적인 데이터센터 환경의 성능 또는 비용 절감률로 직접 환산하는 것은 적절하지 않다.

셋째, 시장 규모, CAGR, 도입 기업 수, 매출, 고객 사례, 표준화 참여 등 시장성 평가에 필요한 정량 정보가 부족하다. 따라서 시장성 평가는 기술 공개성, 개발자 접근성 및 연구·생태계 신호 중심의 정성적 판단에 한정된다.

확증편향을 방지하기 위해 다음의 조치를 적용하였다.

- 기술별 성능 장점뿐 아니라 런타임 의존성, I/O 경합, 프리페치 실패, 운영 복잡성 및 상용화 부족을 함께 기술하였다.
- MLA와 ITME를 단순 경쟁 기술로 규정하지 않고, 해결 계층과 워크로드 특성에 따른 보완 관계를 함께 검토하였다.
- 특정 성능 수치를 일반적 TCO 절감 또는 모든 워크로드의 성능 향상으로 확대 해석하지 않았다.
- 입력 자료에 없는 시장 수치, 고객 사례, 기업 도입 현황, 비용 절감률 및 성능 비교 수치를 추가하지 않았다.
- 근거가 제한된 항목은 “근거 부족” 또는 “추가 검증 필요”로 명시하였다.
